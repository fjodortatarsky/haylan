# Техническое задание: CRM-система для стоматологической клиники «Хай-Лань»

## 1. Общее описание проекта

### 1.1. Назначение
Разработка веб-приложения CRM-системы для управления воронкой продаж стоматологической клиники «Хай-Лань» (г. Хайхэ, Россия/Китай). Система должна автоматизировать процесс работы с лидами, отслеживать этапы продаж, контролировать сроки контактов и рассчитывать комиссии менеджеров.

### 1.2. Целевая аудитория
- **Менеджеры по продажам** — ведут клиентов по воронке
- **Администраторы клиники** — контролируют процесс
- **Руководство** — просматривают финансовую аналитику

### 1.3. Особенности
- **Двуязычный интерфейс** (русский/китайский) — обязательно для всех элементов
- **Адаптивный дизайн** — работа на десктопе и мобильных устройствах
- **Клиентская база** — преимущественно русскоязычные пациенты, обращающиеся в китайскую клинику

## 2. Функциональные требования

### 2.1. Воронка лидов (основной модуль)

#### 2.1.1. Отображение таблицы лидов
- Таблица со следующими колонками:
  - ID, Дата лида, Имя клиента, Телефон, Город, Источник, Запрос
  - Предварительная сумма, Фактическая сумма, Ставка комиссии (%), Комиссия (₽)
  - Этап (из 10 возможных), Статус (из 5 возможных)
  - Последний контакт, Плановый контакт, Менеджер, Комментарий, Причина потери
- Цветовое кодирование этапов и статусов
- Пагинация (50-100 записей на страницу)
- Фильтрация по: этапу, статусу, менеджеру, источнику, датам

#### 2.1.2. Визуализация воронки
- Графическое отображение всех 10 этапов с процентом заполнения
- Клик по этапу → переход к отфильтрованной таблице лидов этого этапа
- Подсчёт количества лидов на каждом этапе

#### 2.1.3. CRUD операции для лидов
- **Создание:** форма с валидацией всех обязательных полей
- **Редактирование:** inline-редактирование или модальное окно
- **Удаление:** мягкое удаление (архивирование)
- **Дублирование:** копирование лида с очисткой дат

#### 2.1.4. Автоматические расчёты
- Комиссия = Фактическая сумма × Ставка %
- Пересчёт при изменении фактической суммы или ставки
- Автоматическое обновление сводной статистики

### 2.2. Справочник этапов воронки

#### 2.2.1. Структура этапов (10 шт.)
1. **Новый лид** (≤1 дня) — менеджер
2. **Предварительная консультация** (≤3 дней) — менеджер
3. **Прогрев** (≤7 дней) — менеджер
4. **Контроль** (≤5 дней) — менеджер + клиника
5. **Подтверждение поездки** (≤3 дней) — клиника
6. **Покупка билетов** (≤2 дней) — менеджер + клиент
7. **Прибытие** (≤1 дня) — клиника
8. **Лечение** (по плану) — клиника
9. **Пост-сервис** (≤14 дней) — менеджер
10. **Потерян** (≤1 дня) — менеджер

#### 2.2.2. Для каждого этапа:
- Название (RU/CN), цвет, порядок
- Действие (что нужно сделать)
- Критерий перехода (условие перехода на следующий этап)
- Срок выполнения
- Ответственный

#### 2.2.3. Редактирование справочника
- Администратор может изменять: сроки, ответственных, описания действий
- Цвета и порядок — только через миграции БД

### 2.3. Справочник статусов

#### 2.3.1. Статусы лидов (5 шт.)
- **В работе** (синий) — активная работа по лиду
- **Ожидает ответа** (жёлтый) — отправлено сообщение, ждём реакции
- **Выполнено** (зелёный) — этап завершён, переход дальше
- **Отложен** (серый) — клиент просил паузу
- **Потерян** (красный) — отказ или нет ответа >14 дней

#### 2.3.2. Бизнес-логика статусов
- Автоматическая смена на «Потерян» если:
  - Статус «Ожидает ответа» >14 дней
  - Нет активности >14 дней
- При смене на «Потерян» — обязательное поле «Причина потери»

### 2.4. Контроль сроков

#### 2.4.1. Сводка по срокам
- **Красные** (просрочены >5 дней) — критично
- **Жёлтые** (1-5 дней) — требуют внимания
- **Зелёные** (в графике) — нормально

#### 2.4.2. Автоматический мониторинг
- Ежедневная проверка плановых контактов
- Уведомления менеджеру за 1 день до планового контакта
- Уведомления администратору о просроченных лидах
- Email/Telegram уведомления (опционально)

#### 2.4.3. Детальная таблица контроля
- ID, Имя, Этап, Последний контакт, Плановый контакт
- Дней до контакта (отрицательное = просрочка)
- Статус срока (красный/жёлтый/зелёный)

### 2.5. Финансы и комиссии

#### 2.5.1. Сводная статистика
- Сумма всех лечений (₽)
- Сумма комиссий (₽)
- Конверсия в лечение (%)
- Средний чек (₽)
- Количество потерянных лидов

#### 2.5.2. Реестр вознаграждений
- ID, Имя клиента, Фактическая сумма, Ставка %, Комиссия
- Статус выплаты:
  - **Ожидает** — лечение завершено, комиссия начислена
  - **Подтверждено** — клиника подтвердила сумму
  - **Выплачено** — менеджер получил выплату
  - **Спорная** — есть разногласия по сумме

#### 2.5.3. Отчёты
- Экспорт в Excel/CSV
- Фильтры по: менеджеру, периоду, статусу выплаты
- Сводка по менеджеру (количество лидов, сумма комиссий, конверсия)

## 7. Пользовательские сценарии

### 7.1. Сценарий: Создание нового лида
1. Менеджер кликает «Новый лид»
2. Открывается форма с полями: Имя, Телефон, Город, Источник, Запрос
3. Автоматически устанавливается:
   - Дата = сегодня
   - Этап = «Новый лид»
   - Статус = «В работе»
   - Плановый контакт = завтра
4. Менеджер заполняет поля и сохраняет
5. Лид появляется в таблице и воронке

### 7.2. Сценарий: Обновление статуса лида
1. Менеджер кликает на ячейку «Статус» в таблице
2. Открывается выпадающий список статусов
3. Менеджер выбирает новый статус
4. Система проверяет бизнес-правила:
   - Если «Потерян» → показать поле «Причина потери»
   - Если «Выполнено» и этап < 10 → предложить следующий этап
5. Изменение сохраняется, обновляется audit_log

### 7.3. Сценарий: Просроченный контакт
1. Ежедневная задача проверяет все лиды
2. Находит лиды с plan_contact_date < today
3. Отправляет уведомление менеджеру:
   - Telegram: «Просрочен контакт с Анна К. (4 дня)»
   - Email: аналогичное сообщение
4. В таблице лид меняет цвет на красный
5. В сводке «Контроль сроков» увеличивается счётчик просроченных

### 7.4. Сценарий: Расчёт комиссии
1. Клиент завершил лечение (этап = 8)
2. Менеджер обновляет фактическую сумму: 69000 ₽
3. Система автоматически рассчитывает: 69000 × 10% = 6900 ₽
4. В реестре вознаграждений появляется запись со статусом «Ожидает»
5. Администратор подтверждает выплату → статус «Подтверждено»
6. Менеджер получает выплату → статус «Выплачено»
